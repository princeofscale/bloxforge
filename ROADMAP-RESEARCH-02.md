
Отчёт о проекте BloxForge
Краткое резюме

BloxForge – это открытый (MIT) инструментальный набор (framework) для интеграции AI-агентов с Roblox Studio. Он реализует локальный сервер протокола Model Context Protocol (MCP) вместе с плагином для Roblox Studio. Это позволяет любому совместимому MCP-клиенту (например, Claude Code, OpenAI Codex CLI, Gemini CLI и т.д.) по локальному каналу «localhost» инспектировать и модифицировать игровые места Roblox (Places). Проект активно развивается: за последнее время (лето 2026) выпущены версии v4.0.0 (31.07.2026), v4.1.0 (05.08.2026) и v4.2.0 (07.08.2026). В репозитории уже 170 коммитов, последний из которых привязан к релизу v4.2.0 (август 2026). Открытых Issues нет (пользовательская подача заявок отключена), открыт один pull request (#86 от 07.08.2026) с доработкой документации.

Основные возможности BloxForge включают управление игровым миром и кодом: построение/редактирование экземпляров, UI, ландшафта, освещения, шаблонов и пр. (Build); чтение, поиск, изменение и валидацию скриптов на языке Luau (Code); автоматические playtest’ы и проверку логики игры (Test); отладочные данные (логи, профили, точки останова) (Debug); интеграцию с существующими инструментами Rojo/Wally/Rokit (Integrate); а также механизмы безопасности: локальная привязка, подтверждение и откат изменений (Protect). Документация содержит подробный Quick-start и примеры, а также модуль безопасности и архитектуры.

Статус проекта: несмотря на то, что многие функции уже реализованы и имеются комплексные проверки, BloxForge всё ещё формально находится на стадии early-beta. Проект интенсивно развивается (релизы в течение одной недели), но основан на новой концепции AI-агентов в Roblox, что может быть экспериментально. Разработчики уделяют внимание надёжности (rollback, атомарность операций, подтверждение планов, локальное выполнение). Риски включают сложность настройки окружения (роблокс-инструменты, разного рода CLIs), возможные баги в сложных сценариях синхронизации, а также зависимость от актуальности внешних сервисов (MCP-клиентов).
Назначение проекта

Цель BloxForge – предоставить безопасный локальный интерфейс для AI-агентов, работающих с Roblox Studio. Проект позиционируется как «AI agent toolkit for Roblox Studio». Идея в том, что агент (например, GPT-4 или Claude Code) запускается через стандартный MCP-протокол, BloxForge получает его команды и передаёт Studio (через плагин) для выполнения. Это позволяет агенту «заглядывать» в игровое место, читать и править скрипты, проводить playtest’ы и т.д., при этом все данные и трафик остаются на машине пользователя. Таким образом, BloxForge действует как мост между Studio и любым AI-клиентом, обеспечивая локальные контроли и безопасность.
Функциональность

BloxForge предоставляет широкий набор функций для автоматизированного конструирования и анализа игр в Roblox:

    Build: создание и изменение объектов игры – инстансов, элементов UI, ландшафта, освещения, шаблонов, моделей и автоматически генерируемых сцен.
    Code: работа со скриптами на Luau – чтение, поиск, патчинг, валидация и безопасная замена исходного кода.
    Test: автоматизация тестирования – запуск playtest’ов, симуляция пользовательского ввода, проверка игровых логик и сравнение состояний (скриншотов, эпизодов).
    Debug: отладка – сбор Runtime-логов, диагностика коммуникации (транспорт), профилирование памяти, установка breakpoints и т.д. (плагин Studio участвует в сборе метаданных).
    Integrate: интеграция со сторонними инструментами Roblox – BloxForge управляет реальными CLI Rojo, Rokit и Wally через их интерфейсы; проводит импорт/экспорт проектов, управление ассетами, фиксирует происхождение изменений.
    Protect: меры безопасности – соединение по локалхосту, ограничение возможностей каждого клиента, системы «предосмотра и подтверждения» операций (plan/apply), поддержка dry-run и откат изменений, журналы восстановления.

Эти возможности подробно описаны в README и связанных документах. Например, Quick Start показывает настройку (Node.js 20+, включение HTTP-запросов в Studio, установка плагина) и подключение к MCP-клиенту. Документация предлагает конкретные сценарии: инспектирование места и формирование плана изменений, автоматическая сборка и тестирование «полного цикла» уровня игры.
Архитектура

BloxForge состоит из двух основных компонентов: Node.js-сервер и плагин Roblox Studio. Архитектура следующая: MCP-клиент (AI-агент) связывается по стандарту MCP с BloxForge сервером на локалхосте, а сервер через HTTP/WebSocket каналы общается с плагином, загруженным в Roblox Studio. Вся передача идёт локально, внешний интернет не используется, поэтому не нужен облачный аккаунт. Пример архитектуры (упрощённо):

mermaid

flowchart TD
    AI[AI MCP-клиент<br/>(Claude/Gemini/Codex)] -->|MCP| Forge[BloxForge Node-сервер]
    Forge -->|HTTP/WebSocket| StudioPlugin[Плагин Roblox Studio]
    StudioPlugin --> Roblox[Roblox Studio]

Как видно, сервер BloxForge исполняет команды агента, а плагин обменивается с Studio API (например, читает scene tree, управляет скриптами, инициирует playtest). Логика инструментов (handlers, builders) реализована в общем модуле packages/core, CLI-утилиты обёрнуты в пакеты @princeofscale/bloxforge и @princeofscale/bloxforge-inspector, а плагин (studio-plugin) компилируется из TypeScript в Luau для Studio.

Зависимости и требования

Для работы BloxForge требуется следующее окружение и сторонние инструменты:

    Node.js версии 20 или новее (мини́мальная поддержка Node 20+, обязательна для исполняемых пакетов).
    npm/yarn для установки пакетов.
    Roblox Studio с включённой опцией «Allow HTTP Requests» (требуется, чтобы плагин мог принимать запросы от сервера).
    MCP-клиент: любой AI-агент, поддерживающий Model Context Protocol (например, Claude Code, OpenAI Codex CLI, Gemini CLI или Cursor CLI). Они запускают bloxforge как MCP-сервер (Quick Start показывает команды).
    Roblox CLI-инструменты (для работы с файловым проектом):
        Rojo (версия ≈7.7.0 или выше) – синхронизация файловой системы с игрой. BloxForge использует Rojo для управления «источником правды» проекта.
        Wally (версия ≈0.3.x) – пакетный менеджер Roblox (управление зависимостями, lockfile). BloxForge умеет вызывать Wally (wally_validate_lock, wally_install, и т.д.) через свои инструменты.
        Rokit/Aftman – система управления версионированием инструментов (указывает, какие версии Rojo/Wally/StyLua/Selene использовать). Проект предусматривает пиннинг версий в rokit.toml.
    Опционально: Инструменты для проверки качества кода Luau (StyLua, Selene) – BloxForge не включает их, но README рекомендует запускать их локально для Lint/format.
    Зависимости npm (упомянуты в package.json): @modelcontextprotocol/sdk (MCP-протокол) версии ^1.30.0, express ^4.22.2 (HTTP сервер) и ws ^8.21.1 (WebSocket). Эти библиотеки отвечают за сетевой слой и взаимодействие с MCP.

Наличие актуальных версий вышеуказанных утилит критично для корректной работы. В документации отмечено, что под проект «pin-ится» версия Rojo 7.7.0, а отсутствие установленного шима приводит к ошибке, вместо молча запуска глобального Rojo.

Безопасность и уязвимости

Серьёзное внимание уделено надёжности и безопасности. Система спроектирована так, чтобы изменять состояние Studio только через явное подтверждение (двухэтапные операции plan/confirm). Принципы безопасности из README: локальная привязка по умолчанию, строгие библиотеки сертификации и scoped-токены, атомарность изменений, поддержка dry-run и логирование. Например, плагин не допускает прямых сетевых запросов без проверки, а сервер отвергает любые команды, если состояние файлов не совпадает с запланированным. В changelog упоминаются также специальные меры: устойчивость к ошибкам TOML, схемам данных, а также готовность к recovery (журналы, rollback).

Авторы заявляют, что уязвимостей в npm-зависимостях (production) нет: после обновлений npm audit не выявляет проблем. Однако стоит учитывать риски сторонних компонентов (Rojo, Wally и др.) и вовремя обновлять зависимости. Процесс обработки ошибок схож с «fail-safe»: при любой непредвиденной ситуации (например, несогласованность lockfile, повреждение State-файла) система откатывается и выводит понятное сообщение (RFC на GitHub предлагает private-security report). В справке имеется SECURITY.md для сообщений об уязвимостях. На данный момент общедоступных CVE или известных эксплойтов BloxForge не зафиксировано (только локальные функции).
Совместимость и интеграции

BloxForge нацелен на кроссплатформенную совместимость, так как основан на Node.js и не имеет специфичных нативных модулей. Работает в любой ОС, поддерживающей Node 20+ и Roblox Studio. В CI указано тестирование на Windows и macOS (см. .github/workflows). Взаимодействует со следующими компонентами:

    Roblox Studio (любой актуальной версии, желательно последней; требуется включение HTTP Service).
    Rojo 7.7.0+ (для «файловых» проектов). Интегрируется через командную строку Rojo (MCP-инструменты rojo_*).
    Wally 0.3.x (для управления пакетами Roblox). BloxForge вызывает wally_validate_lock, wally_install и т.д., проверяя сопоставление директорий с проектом.
    Rokit/Aftman (для выбора версий инструментов). Информация о версиях Rojo/Wally/Stylua/Selene хранится в rokit.toml, BloxForge учитывает эти пины (см. изменения в changelog про поиск исполняемых файлов по схеме шима).
    MCP-клиенты: такие как Claude, Codex, Gemini, Cursor. BloxForge совместим с любым клиентом, использующим стандарт MCP; Quick Start даёт примеры настройки MCP-серверов для разных систем.
    OpenAI API (необязательно): с выходом новых фич Roblox появилась возможность загружать места через Open Cloud API; BloxForge поддерживает передачу API-ключа для доступа к Creator-Store и загрузке ассетов.

Примеры использования и документация

Документация BloxForge (помимо README) включает Tools Reference, Architecture, Known Limitations, Troubleshooting и прочие руководства (в папке docs/). README уже содержит краткую инструкцию по установке плагина и подключению MCP-клиента. Примеры применения описаны в разделе "Try it": например, «Inspect this place, summarize its architecture, identify runtime risks, and propose a safe plan» или «Build a six-stage obby…».

Для запуска проекта рекомендуется:

    Клонировать репозиторий и установить зависимости: npm ci.
    Собрать пакеты: npm run build:all.
    Установить плагин в Roblox Studio: npx -y @princeofscale/bloxforge@latest --install-plugin.
    Подключить MCP-клиент (например, claude mcp add bloxforge -- npx -y @princeofscale/bloxforge@latest).
    Проверить соединение: npx -y @princeofscale/bloxforge@latest verify.

Тесты выполняются командой npm test или npm run test:rojo:integration (после установки Rojo 7.7.0). Авторы также рекомендую дополнительные проверки: npm run test:plugin:smoke, npm run docs:check, npm run verify-package.
Альтернативы и конкуренты

В официальной документации альтернативы не упоминаются. BloxForge уникален в своей специализации: AI-интеграция с Roblox Studio. Прямых конкурентных проектов с открытым исходным кодом на текущий момент не зафиксировано (есть лишь экспериментальные подходы, см. обсуждения на форумах). В целом, можно сказать «альтернативы не указаны» – аналогичных инструментов для AI-агентов в Roblox пока не распространено.
Выводы и рекомендации

BloxForge – зрелый и функциональный инструмент для экспериментов с AI в разработке Roblox-игр. Он уже позволяет автоматизировать многие задачи (создание уровней, изменение кода, тестирование). Тем не менее, проект находится на стадии активной разработки: появляются новые релизы и функции каждую неделю, а нет общего статуса «production-ready». Стоит оценивать его как Beta/Experimental: он стабилен для исследований, но перед промышленным использованием нужно тщательно протестировать конкретные сценарии.

Рекомендации по использованию: начать с ознакомления README и Quick Start (установка Node.js 20+, плагина и настройка MCP). Затем попробовать стандартный сценарий: запустить агента (Codex или Claude), дать ему простую задачу над открытым местом в Studio. Использовать профили инструментов (--profile builder, --profile tester) для ограничений объёма задач. В случае проблем – смотреть раздел Troubleshooting, Known Limitations. Рекомендуется выполнять все изменения через предложенную цепочку план/подтверждение (*syncback_plan → review → confirm) и всегда хранить резервные копии проектов.

Тестирование и вклад: локально проект строится через npm, есть юнит- и интеграционные тесты. Для вклада нужно соблюдать кодстайл и правила ревью (есть CONTRIBUTING.md). Автор приветствует pull request’ы с фиксацией найденных ошибок и улучшением документации. Перед PR полезно запустить npm run test и npm run docs:check.

В заключение: BloxForge – мощный инструмент для AI-разработки в Roblox, предлагающий полную интеграцию с экосистемой Roblox. Он предлагает богатые возможности, но требует аккуратной настройки окружения. Рекомендуем начинать с небольших экспериментов, тщательно читать документацию и участвовать в сообществе (Telegram-канал, GitHub) для получения обновлений и помощи.
